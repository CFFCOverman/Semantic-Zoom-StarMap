# 度量
这套架构有没有在起作用，看数，不看印象。数从 `.sza/history/log.jsonl` 算：运行 python3 sza.py stats。命令和日志字段写在 sza.py 的文件头。
1. **过时事故：** 改了一处，别处该跟着变却没变，事后才发现。这是本架构要治的病，发现一次记一次：python3 sza.py incident <出问题的文件> "说明"。
2. **没跟引用：** AI 没打开引用指向的那个文件就动手，结果做错。同样记一次，加 --kind skipped。
3. **检查拦下：** done 或提交前钩子查出断链、结构问题的次数，sza.py 自动记。长期为 0 而事故不为 0，说明检查没查到点上。
4. **波及：** 每次改动有几处引用它、实际动了几个文件，sza.py 自动记。参数级或内部级的改动动了不止一个文件，算一次定级不符：要么级别定低了，要么有定义没收在一处。
5. **怎么读：** 先攒两周当基线，再看趋势。事故率往下走、后三项不往上走，才算有用。`params.ref_hops_max` 这类阈值按这些数调，不凭一次印象改规则。
6. **没有 sza.py 时：** 记不了日志，在交付说明里写明这次改动没进度量。
